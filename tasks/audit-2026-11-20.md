## P1 — срочно

### 1. Smoke-гейт красный на каждом запуске (с 11 октября)

GitHub Actions, workflow `smoke.yml`, шаг «Run smoke suite» — `failure` в 5 из 5 последних запусков:
`44608429381` (19.11, мой пуш), `44606817348` (19.11), `38228625801`, `38222433070`, `38151264005` (11–12.10).
Deploy и docs-check при этом зелёные — сайт обновляется, но контроль качества мёртв.

Локальное воспроизведение (полный прогон, 97/284 до остановки): 3 падения —
`#root-dictionary` (панель не стала видимой за 5 с), `#linguistic-tensor` (`console.error` из обработанного `fetch` в `religionisms.js:59`), `#exposure-masoretic` (SW: «unknown error when fetching the script»).
Повторный точечный прогон этих трёх маршрутов — **3/3 passed**. То есть это флаки, а не дефекты экранов.

Причины-кандидаты (все подтверждаются кодом):
- `playwright.config.js` не блокирует Service Worker (`serviceWorkers: 'block'` отсутствует), а `index.html:1217` его регистрирует. Кэш SWR отдаёт старые ответы и шумит сетевыми ошибками;
- статический сервер для тестов — `python -m http.server`; при 180+ параллельных запросах на бут бывают `ERR_CONNECTION_REFUSED` (наблюдал лично);
- таймаут видимости 5 с на голодном буте;
- `checkRoute` считает падением любой `console.error`, включая штатно обработанные ошибки загрузки данных;
- фильтр `Failed to load resource:` скрывает именно тот класс ошибок, который ловит битые пути (см. P2-1).

**Фикс:** `serviceWorkers: 'block'` в конфиге; поднять таймауты; не считать `console.error` из `catch` падением (или логировать `warn`); проверить лог шага в Actions; после — закрепить зелёный прогон.

### 2. Агентные тесты: 3 падения из 119, в CI не запускаются

`py -m unittest discover -s tests` в `products/agents` → `Ran 119 tests, FAILED (failures=3)`.
Все три — один корень: `docs/01-ARCHITECTURE/ARCHITECTURE.md:190` заявляет «133 файла данных», на диске **134** (90 CSS + 86 JS + 134 JSON). Тест `arch_critic` видит расхождение и валит три проверки дрейфа.

Дополнительно: тесты **негерметичны** — прогон переписал отслеживаемый `docs/13-REPORTS/ARCH-DRIFT.md` (восстановил через `git checkout`), а тест-сид пишет прямо в `ARCHITECTURE.md`.

**Фикс:** 133 → 134 в ARCHITECTURE.md; тесты — на копии документов (tmpdir); добавить агентные тесты в CI.

### 3. Локальный сервер агентов: CORS `*` + мутации без аутентификации

`products/agents/server.py`:
- `Access-Control-Allow-Origin: *` на все ответы (стр. 176–186);
- `POST /api/lab/shutdown` и `/api/lab/restart` без токена (стр. 363–395) — любой сайт, открытый в браузере, пока сервер запущен, может погасить/перезапустить его;
- `POST /run`, `/api/run`, `/api/pipelines/<id>/run` без токена — можно гонять агентов (Ollama) чужими руками;
- запись файлов ограничена `WRITABLE_PIPELINES = {"arch_keeper"}` + флаг `writeEnabled` (стр. 88, 448), но флаг передаёт кто угодно.

Сервер слушает `127.0.0.1` (стр. 602) — это снижает риск до локального, но браузер страницы из интернета тоже локальный.

**Фикс:** CORS по умолчанию выключить (или allowlist `127.0.0.1:4173`), ввести сессионный токен (печатать при старте, требовать на POST), `shutdown/restart` — только с токеном.
