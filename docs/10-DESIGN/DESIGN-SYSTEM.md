# ALEPHY · Дизайн-система «Современный манускрипт»

Версия: 2.0 · Статус: канон · Источник токенов: `css/tokens.css`
Продукты: Research Lab (`apps/researchlab/`), Лендинг (`products/website/`)

---

## 0. Принципы

### 0.1 Доктрина трёх голосов
Каждый слой дизайна имеет одного хозяина:

| Голос | Владеет | Средства |
|---|---|---|
| **Артефакт (палео)** | содержание | глифы, золотые акценты, пергаментные фактуры, сериф в display-заголовках |
| **Зал (минимализм)** | структура | 8px-сетка, воздух, hairline-рамки 1px, нейтральные поверхности |
| **Свет (футуризм)** | поведение | easing 120–200ms, backdrop-blur в моменты взаимодействия, микро-взаимодействия |

### 0.2 Правила-законы
- Палео — только в контенте, **никогда в хроме** (кнопки, инпуты, сайдбар, тулбары).
- **Тени = ноль в новом UI.** Состояние показывают hairline-рамки 1px и фоны. Тени живут только в glass-слое и legacy-композитах до их миграции.
- 90/10: 90% экрана — тихий минимализм, ≤10% — палео-акценты.
- Стекло (liquid glass) = **витрина**: только оверлеи (модалки, тосты, палитры, sticky-шапка при скролле, search-панель). Постоянный UI — матовый.
- Различение эмет/шекер распространяется на UI: статусы и уверенность всегда видимы (раздел 6).
- reduced-motion respected всегда.

## 1. Токены

### 1.1 Цветовые роли
Роли (не имена цветов!) переопределяются каждой темой:

| Роль | Light (пергамент) | Назначение |
|---|---|---|
| `--bg-primary` | `#ede0c8` | фон страницы |
| `--bg-secondary` | `#faf3e0` | поверхности карточек |
| `--bg-tertiary` | `#f5edd5` | вложенные поверхности |
| `--bg-dark` | `#2c1810` | ink-поверхности, тёмные ячейки |
| `--text-primary` | `#2c1810` | основной текст |
| `--text-muted` | `#8a7a6a` | мета, подписи |
| `--text-on-accent` | `#fffaf0` | текст на золоте |
| `--border-light` | `#d4c4a8` | hairline-рамки |
| `--accent-gold` | `#b8860b` | единственный акцент |
| `--accent-red` | `#c0392b` | ошибка/разрушение (дозированно) |
| `--scrim` | `rgba(0,0,0,.5)` | затемнение под модальными оверлеями (`::backdrop`) |

Запрещено: новые hex в компонентах; «семейные» оттенки вне ролей; чужие палитры (admin-синий и т.п.) — мигрируются в роли.

Композиции для читаемости: текстовые версии акцентов — токены `--gold-text` / `--red-text` (`color-mix` 65% золота и 72% красного к цвету текста темы, ≥4.5:1 во всех темах; источник — `css/tokens.css`). Второй план текста на светлых панелях берёт `--text-secondary`: `--text-muted` как текст в темах light/white/beige не добирает AA (3.74 / 3.61 / 2.79:1) — фон и hairline-роли это не касается.

### 1.2 Типографика
Шрифты: **EB Garamond** (сериф: display, заголовки, цитаты) + **DM Sans** (UI: мета, лейблы, кнопки).

| Токен | px | Применение |
|---|---|---|
| `--ui-10/11/12/13` | 10/11/12/13 | плотный UI: бейджи, лейблы, мета |
| `--text-14` | 14 | компактный UI-текст |
| `--text-xs/sm/md/base` | 12/13/15/16 | основной текст |
| `--text-lg/xl/2xl/3xl` | 18/22/28/38 | заголовки |
| `--text-hero/--text-section` | clamp | hero и секции (лендинг) |

Uppercase-лейблы секций: `--ui-11`, letter-spacing .08em, цвет `--text-muted`.

### 1.3 Spacing
`--space-1..8` = **4 / 8 / 12 / 16 / 20 / 24 / 32 / 48**. Другие значения запрещены; микроступени чипов (2/6px) — только по явной записи здесь.

### 1.4 Радиусы
`--radius-xs 4 / sm 6 / -8 8 / md 10 / lg 14 / xl 20 / pill 999`.
Карточки и панели: `-8` или `md`. Чипы/бейджи: `pill`. Квадратные глиф-чипы: `sm`.

### 1.5 Тени и стекло
- Новый UI: **без теней** (hairline-рамки).
- Legacy-канон до миграции: `--shadow-soft / -card / -hover / -modal / -floating`, `--ring-focus`.
- Glass-токены: `--glass-bg`, `--glass-blur`, `--glass-shadow`, `--header-glass-mix`.
- Реестр стекла: модалки, тосты, палитры-оверлеи, `.glass-topbar.is-scrolled`, `.glass-search-panel`. Новое стекло — только через правку этого реестра.

### 1.6 Z-шкала
`--z-behind -1 · --z-content 1 · --z-topbar 1000 · --z-search 999 · --z-modal 9998 · --z-toast 10000`. Литеральные z-index запрещены.

### 1.7 Контейнеры
`--shell-frame 1400` (каркас) · `--shell-page 1120` (страница) · `--shell-read` (читалка, ch-меры) · `--shell-wide` (полотна карт).
`.lab-container { max-width: var(--shell-page); margin-inline:auto; padding-inline: var(--space-5); }` (mobile: `--space-3`).
**Закон краёв:** каждый блок страницы краями совпадает с контейнером шапки.

### 1.8 Motion
120–200ms, `cubic-bezier(.2,.7,.2,1)`; метафоры: чернила (проявление), свиток (раскрытие). Stagger ≤ 40ms/элемент, серии ≤ 6. Никаких animation-timeline-разлётов.

## 2. Темы
Четыре темы через `[data-theme]`: **light** (пергамент), **dark** (ink), **brown** (шоколад), **white** (чистая бумага). Каждая определяет полный набор ролей + `--header-ink`, `--header-ink-muted`, `--header-glass-mix`. Контраст текст/фон ≥ 4.5:1, иконки ≥ 3:1 в каждой теме. Новая пара «цвет+фон» = 4 переопределения и запись здесь.

## 4. Компоненты

### 4.1 Заголовок секции
Uppercase `--ui-11` + волосяная линия 1px `--border-light` под ним + опциональный бейдж-счётчик (круг 20px, hairline) справа. Это маркер границ панели (эталон: палео-конструктор).

Общий каркас панелей и глав — `css/components/panels.css`: `.lab-panel` (hairline-панель без теней), `.lab-panel-row` (ряд панелей: две колонки → стек), `.lab-chapter` + `.lab-chapter-num` + `.lab-chapter-title` (номер, uppercase-микролейбл, одна волосяная линия; селектор задан сильнее `.module h2:not(:last-child)` из `layout.css`, иначе h2 перед бейджем раздувается в сериф), `.lab-chapter-note`, `.lab-empty` + `.lab-empty-glyph` + `.lab-empty-hint` (§4.6), `.lab-skeleton` (состояние running), `.lab-examples` + `.lab-example-chip` (чипы примеров), `.lab-status` (+ `is-error` / `is-success`). Модули дублируют только свою специфику (`.vl-*`, `.rc-*`), а не каркас.

#### 4.1a Шапка ячейки bento (обязательно для новых ячеек)
Шапка ячейки — **не** `<h2>`-заголовок в общем смысле, а микролейбл полосы. Разница видна глазом, поэтому соблюдение обязательно.

**Линия — только на полосе шапки, во всю ширину ячейки.** Короткая черта под самим текстом — дефект, а не украшение: она появляется там, где заголовок не сбросил `border-bottom`/`padding` базового `.module h2:not(:last-child)` (`css/layout.css`), и обрезается по ширине текста вместо ширины ячейки.

Обязательные свойства заголовка ячейки — ровно такие, единый размер для всех ячеек модуля и для всех модулей лаба:

```css
/* Селектор с .module обязателен: базовое .module h2:not(:last-child)
   из layout.css (специфичность 0,2,1) иначе перебьёт одиночный класс
   и напечатает капитель крупным серифом. */
.module .xx-cell .xx-cell-title {
  margin: 0;
  padding: 0;
  border-bottom: 0;            /* сброс базового h2 — чёрка живёт на .xx-cell-head */
  color: var(--text-secondary);
  font-family: var(--font-ui); /* не --font-heading: это лейбл, не заголовок */
  font-size: var(--ui-11);
  font-weight: 700;
  letter-spacing: var(--tracking-caps);
  text-transform: uppercase;
}
```

| Свойство | Значение | Почему |
|---|---|---|
| размер | `--ui-11` | единственная ступень лейблов ячейки; «свой» кегль = разнобой между ячейками |
| вес | 700 | 600 выглядит как обычный текст рядом с номером главы |
| трекинг | `var(--tracking-caps)` | литерал `.08em` запрещён — разъедется при правке токена |
| шрифт | `var(--font-ui)` | сериф оставлен заголовкам страницы, не полосам ячеек |
| цвет | `--text-secondary` | на ink-ячейке — `--header-ink-muted` |

Номер главы (`.xx-num`) — mono `--ui-11`; подпись справа (`.xx-cell-hint`) — `--ui-12` mono, `--text-muted`, `margin-left: auto`. Числа, лейбл и подпись обязаны быть одного размера `--ui-11`/`--ui-12`, иначе строка шапки разъезжается по вертикали.

Перед копированием шапки в новый модуль проверьте, что в селекторе есть `.module` **и** `border-bottom: 0`. Эталон: `css/religionisms.css` (`.rel-cell-head` / `.rel-cell-title`), `css/scripture-reader-bento.css`, `css/workbench-bento.css`.

### 4.2 Карточка
Компактная (~140px): мета-строка (статус-точка + категория-чип + дата справа) → сериф-заголовок ≤2 строк → описание 1 строка ellipsis → до 3 мини-чипов терминов (нет — строки нет). Рамка 1px, radius `-8`, без теней; hover: рамка → `--accent-gold` + подложка rgba(gold,.06).

### 4.3 Чипы и бейджи
Чип: pill, hairline, `--ui-12`, padding 2px 10px. Бейдж статуса/уверенности — раздел 6. Категории — uppercase `--ui-10`.

### 4.4 Кнопки
- Primary: `--accent-gold`, текст `--text-on-accent`, radius `-8`; в панелях — во всю ширину панели.
- Secondary: hairline-рамка, текст `--text-primary`.
- Icon: 32–36px квадрат, hairline; ряд без переносов (mobile ≤2 ровных рядов).
- Compact: icon 16px + текст, для тулбаров.

### 4.5 Инпуты и селекты
Hairline-рамка, radius `-8`, фон `--bg-secondary`; focus: `--ring-focus` или outline 2px (не glow). Лейблы над полями в тулбарах запрещены — placeholder несёт смысл.

### 4.6 Empty-state
Пунктирная рамка 1px, глиф по центру (opacity .35), подсказка `--text-muted`. Язык: «Поле ждёт первый знак», «Начните диалог».

### 4.7 Тулбар
Панель в 1–2 строки: search flex-1 + select + compact-кнопка; строка 2: чипы-фильтры + счётчик «N из M» справа + sort-select. Три визуальных этажа запрещены.

Панель стоит **сразу под шапкой модуля**: хром каталога читается сверху вниз, а полоса прогресса и CTA относятся уже к содержимому. В «Обучении» (`#learn`) это единственный модуль, где тулбар идёт перед строкой прогресса, а не после неё.

### 4.8 Список-режим
Строки 48px: статус-точка | заголовок ellipsis | категория | дата. Mobile: 2 линии. Переключатель вид: lucide LayoutGrid/List, выбор в localStorage.

### 4.9 Модалки и оверлеи
Glass-витрина (раздел 1.5): blur + полупрозрачный фон темы, radius `lg`, `--z-modal`. Закрытие: Escape, клик вне, крестик.

### 4.10 Тосты
Glass, `--z-toast`, 4s, reduced-motion — без анимации.

### 4.11 Диаграмма состояний (донат)
Восемь долей кодируются **кураторской рампой токенов**, а не произвольной палитрой: ранг 0 (доминанта) — `--accent-gold`, ранги 1–7 — ступени `color-mix(in srgb, var(--accent-gold) 78…22%, var(--text-primary))` (классы `.stc-tone-0…7`, эталон `css/state-checker.css`). Сегменты разделены hairline-обводкой `var(--bg-card)`; зелёный, синий и красный в диаграмме и легенде запрещены. Центр доната: процент текстом `--gold-text` + подпись «доминирует» (`--text-secondary`, uppercase `--ui-10`). Легенда — мини-чипы состояния (палео-глиф + имя + доля).

---


### 4.12 Полоса-статистика (бары)
Три тонких полосы в одной строке-сетке: подпись (`--text-sm`, `--text-secondary`) → полоса-трек (высота 3px, `--border-light`, radius `pill`) → значение `%` моноспейсом (`--ui-12`, `--text-primary`) справа. Заливка полосы — семантика легенды §6: совпадения `--accent-gold`, расхождения `--red-text`, отсутствующие/нейтраль `--text-secondary`; цветной текст запрещён — цвет несёт только полоса. Эталон: `css/checkers-comparator.css` (`.tc-bar-*`).

## 5. Layout-паттерны

### 5.1 Модуль лаба
Hero-карточка (лейбл «АЛЕФИ · МОДУЛЬ», сериф-заголовок, подзаголовок, бледный глиф 4%) → контент панелями по 4.1. Две колонки desktop → одна mobile (стек по приоритету).
Поле `glyph` в реестре `LabHero.TARGETS` добавляет квадратный глиф-чип справа от текста шапки (палео-глиф, hairline `currentColor`, radius `sm`), `glyphIcon` — тот же чип с lucide-иконкой (эталон: `#video-lab`, `clapperboard`); эмодзи и растровые метки в шапке запрещены (раздел 3). `titleTone: 'ink'` отдаёт заголовок шапки чернильным серифом (`--text-on-dark`) вместо золота (эталон: `#tree-checker`). Чип в `meta` с полем `action` рендерится кнопкой (`data-lab-action`) — так модуль держит строку быстрой проверки в футере шапки; `key` в чипе задаёт i18n-ключ подписи.

### 5.2 Лендинг (bento-манускрипт)
12-col grid, gap 12–16; ячейки hairline, radius 12, без теней; фоны paper/parchment + 1–2 ink-ячейки; золото только акцент; hover: рамка→золото + оживление мини-визуализации.

### 5.2a Модульный bento (bento-инструмент)
Разрешён внутри лаба для инструментов с несколькими разнородными зонами (эталон: `#vision`, `css/vision.css`). Сетка 12 колонок, gap `--space-3`; ячейка = `.vi-cell` (hairline `--line`, radius `-8`, фон `--surface`, тени = 0) с шапкой `.vi-cell-head` по §4.1: номер главы (`.vi-num`, mono, `--ui-11`) + uppercase-заголовок + необязательная подпись справа (`.vi-cell-hint`). Шапка ячейки — **по §4.1a**: единый `--ui-11`/700/`var(--tracking-caps)` на всех ячейках, линия только на `.vi-cell-head` во всю ширину, в селекторе заголовка обязателен `.module` и сброс `border-bottom` — иначе базовый `.module h2:not(:last-child)` напечатает крупный сериф с короткой чёркой под текстом. Пропорции задаёт класс ячейки: поле ввода занимает 7 колонок и две строки, служебные ячейки — по 5, ячейка результата — `1 / -1`. Интерактивная ячейка (dropzone) — dashed-рамка по §4.6, hover/focus-visible → рамка `--accent-gold`. Переключатель режима — сегменты `.vi-segment-btn` с золотой заливкой активного и `aria-pressed`. Зона загрузки принимает drag & drop, а скрытый `input[type=file]` доступен и кликом, и с клавиатуры (`role=button`, Enter/Space). На mobile (≤760px) все ячейки становятся `1 / -1` — закон §5.3.

Вспомогательные блоки внутри ячейки:

- **Сетка способностей** `.vi-caps` — 2 колонки, карточка `.vi-cap` = иконка 16px золотом + заголовок + строка описания, фон `--surface-2`, `overflow-wrap: anywhere` (узкая колонка bento обрезает длинные слова). Это способ избежать наследования `ul` от модульных стилей, возвращающего маркеры и `padding-left`.
- **Оговорка о статусе** `.vi-caveat` — левая золотая линия 2px, фон `--surface-3`, `margin-top: auto` прижимает к низу ячейки. Формулирует, что даёт инструмент: интерпретацию, а не факт (§6).
- **Адрес назначения** `.vi-endpoint` и **сводка запуска** `.vi-recipe` (`dl` с рядами `dt`/`dd`) — показывают, куда уходит запрос и что именно отправляется, до нажатия кнопки.
- **Метаданные файла** `.vi-file-meta` — mono, `--ui-12`, `overflow-wrap: anywhere`; имя, вес и реальные пиксели загруженного снимка.
- **Вложенные контролы кликабельной зоны.** Если зона-обёртка гасит события у детей (`pointer-events: none`), исключение обязано покрывать весь контейнер кнопок (`.vi-drop .vi-preview-actions, .vi-drop .vi-preview-actions *`), а не отдельный класс кнопки: иначе `.vi-drop` перехватывает клик, и визуально живая кнопка не работает.

#### 5.2b Bento настроек (`#settings`, `css/user-preferences.css`)

Второй эталон bento: панель личных настроек. Повторяет §5.2a, но с префиксом `up-` и без зоны загрузки. Ячейка `.up-cell` + шапка `.up-cell-head` (`.up-num` / `.up-cell-title` / `.up-cell-hint`); пропорции — образец темы 5 колонок и две строки, остальные ячейки попарно 7/5.

- **Образцы тем** `.up-swatch` — кнопка с полосой-превью (`.up-swatch-chip`: фон → золото → текст) вместо `<select>`: палитру нельзя увидеть в выпадающем списке. Цвета полосы приходят из `PRESETS.theme[...].vars` в inline-переменные `--sw-*` — хардкод палитры в CSS запрещён. Актив `is-active` + `aria-pressed`, оба ведутся в одном обработчике вместе с сегментами.
- **Живой образец темы** `.up-preview` — мини-страница (заголовок, основной текст, вторичный текст, чип) на цветах выбранной темы через `--pv-*`; `margin-top: auto` прижимает к низу высокой ячейки, иначе под образцами остаётся пустота.
- **Итоговая ячейка** `.up-recipe` — `dl` с текущими значениями, обновляется на лету (`updateSummary`) без перерисовки панели: форма показывает выбор, сводка — результат.
- **Скрытый инпут должен оставаться в фокусе.** Тумблер `.up-toggle` прячет `input` через `clip`, а не `display: none` (иначе он выпадает из фокуса и недоступен с клавиатуры). Клик идёт по `label`; в Playwright кликать нужно по `.up-toggle`, а не по `#input` — под слайдером инпут не попадает в цель.

Правило страницы: настройка, которая только пишет в `localStorage` и ничего не читает, — мёртвая. Каждый переключатель обязан иметь читателя (`#vision` → `data-breadcrumbs` в `router.js` → `renderBreadcrumbs`), иначе контрол удаляется, а не чинится.

#### 5.2e Bento карты (`#cartography` → внутренняя страница, `css/cartography.css`)

Пятый эталон bento: страница одной карты. Префикс `cmb-`, повторяет §5.2a — 12 колонок, gap `--space-3`, ячейка `.cmb-cell` (hairline, radius `--radius-8`, тени = 0), шапка `.cmb-cell-head` по §4.1. Нумерация 01–04.

| Ячейка | Пропорции | Содержание |
|---|---|---|
| `--map` (01) | 8 колонок, 2 строки | SVG карты: перетаскивание, зум, страны-цели |
| `--slice` (02) | 4 колонки | Срез по теме: распределение доминирующих состояний / зон / реестра |
| `--passport` (03) | 4 колонки | Паспорт выбранного объекта: материк, диагноз, доли состояний |
| `--list` (04) | `1 / -1` | Список объектов темы: строки стран или чипы зон |

- **Панель вместо кнопки «Назад к темам».** Общий `.lab-toolbar` (§4.7) несёт поиск, масштаб, счётчик и выход в каталог. Отдельная кнопка возврата под заголовком карты была вторым способом сделать то же самое и занимала отдельную полосу.
- **Один выбор на три входа.** `mapSelection` — общий источник правды для карты, списка и паспорта; обратный индекс `mapIdByName` связывает название государства из списка с id пути из SVG. Перерисовка всей страницы на клике сбрасывала бы масштаб и фокус в поиске, поэтому `refreshMapPanels` меняет только ячейки 03 и 04 и счётчик.
- **Масштаб — в transform, а не в ререндер.** `applyViewport` пишет `transform` у `.world-map-viewport`; кнопки зума не перерисовывают страницу.
- **Модалка заменена ячейкой.** Диагноз страны и паспорт обелиска открываются в ячейке 03, поэтому карта остаётся на экране при выборе.
- **Данные ячейки 03 — доли, а не только название.** Восемь состояний с процентами от суммы по стране: видно не только доминирующее состояние, но и его вес.
- **Шапка ячейки — только лейбл.** `.cmb-num` и `.cmb-cell-hint` моноширинные `--ui-10`, лейбл капителью `--ui-11`. Селектор заголовка задан как `.module .cmb-cell h2.cmb-cell-title`: базовое `.module h2:not(:last-child)` (0,2,1) из `layout.css` сильнее одиночного класса и раздувало лейбл до серифа `--text-2xl` с коротким подчёркиванием — ровно то, что §5.2a и §5.2d уже погасили у себя.
- **Зум — компактный сегмент.** Кнопки `−`/`+` собраны в `.lab-toolbar-zoom`: общая hairline-рамка, `--control-h` (28px), иконка 14px. Прежние `.lab-toolbar-reset` были 40×40 и вдвое крупнее соседних контролов панели.
- **Зум держит точку под курсором.** `zoomMap` пересчитывает `mapPan` относительно позиции указателя, поэтому колесо (`deltaY` на SVG, `passive: false`) и кнопки масштабируют вокруг одной точки; на `--zoom-min` сдвиг обнуляется. `openThemeMap` сбрасывает масштаб и выбор — они относятся к прежней карте.
- **Выделение синхронно в трёх местах.** `selectionKey()` даёт один ключ (`country:<имя>` / `obelisk:<index>`), `markSelectedOnMap` вешает `is-selected` на путь страны, строку списка, чип зоны и маркер обелиска.
- Mobile: ≤1024px карта во всю ширину, срез и паспорт по 6 колонок; ≤760px всё в одну колонку — §5.3.

#### 5.2d Bento разбора слов (`#word-analyzer`, `css/word-analyzer-bento.css`)

Префикс `wab-`, повторяет §5.2a — сетка `.wab-page` на 12 колонок, gap `--space-3`, ячейка `.wab-cell` (hairline, radius `-8`, тени = 0), шапка `.wab-cell-head` по §4.1 (`.wab-num` mono `--ui-11` + uppercase-заголовок + `.wab-cell-hint`). Нумерация сквозная: каркас страницы задаёт ячейки 01–04, `js/word-analyzer-bento.js` продолжает её с 05.

| `--run` (02) | 5 колонок | «Разобрать»/«Очистить», статус `#wa-status`, экспорт Markdown/TXT |

#### 5.2c Bento дизайн-системы (`#design-system`, `css/design-system.css`)

Третий эталон bento и первый модуль, который показывает сам себя. Префикс `ds-`, те же 12 колонок и hairline-рамки, но четыре отличия от §5.2a/§5.2b:

- **Токены читаются из `getComputedStyle`, а не зашиты.** Значения берутся из `document.documentElement` в момент рендера, поэтому образцы отражают текущую тему. Узлы-носители значения помечены `data-ds-token="--…"`, а `MutationObserver` на `data-theme` пересчитывает подписи на месте. Это обязательно: `page-controller` пропускает повторный рендер уже загруженной панели (`dataset.loaded`), поэтому без наблюдателя модуль показывал бы цвета предыдущей темы. По той же причине клик по значению копирует `var(--token)`: значение токена на витрине нужно в буфер обмена чаще, чем просто прочитать.
- **Модуль показывает собственный долг.** Измеренные значения контраста, не дотягивающие до §7, печатаются в ячейке как оговорка `.ds-caveat`, а не прячутся: `.lab-btn-primary` — 2.73:1, `.lab-btn-secondary` — 2.94:1. Правка затрагивает все модули лаборатории и требует отдельного ADR, поэтому не выполняется молча в модуле-витрине.
- **Типографическая лестница — настоящие классы.** `.ds-type-3xl…ds-type-ui` применяют `--text-*`/`--ui-*` к живому тексту; сравнение в smoke-тесте сверяет `fontSize` с `--text-3xl` из токенов, поэтому случайная подмена размера роняет прогон.
- **Плотность витрины задаётся явным сбросом.** Манифестный слой (`components/manifest.css`) даёт `.lab-content .module p { margin-bottom: 20px; max-width: 750px }` — это мера читателя для прозы, а витрина токенов должна читаться таблицей. Поэтому `.ds-cell` сбрасывает `margin` и `max-width` у потомков селектором той же специфичности (`.lab-content .module .ds-cell p`), а ритм задаёт `gap` ячейки. Обёртка `.ds-voices` обязательна: без неё три голоса становились прямыми потомками flex-ячейки и сетка `repeat(3, …)` не применялась вовсе. Пары ячеек дают ровно 12 колонок (7+5): при 7+7 вторая ячейка переносилась вниз и оставляла в строке пять пустых колонок.
- **`flex: 0 0 100%` не переносится из строки в колонку.** `.ds-samples` — flex-колонка, и в ней процентная `flex-basis` считается от высоты контейнера, а не ширины. Метки-разделители секций («Кнопки §4.4», «Чипы §4.3»…) получили высоту во всю ячейку каждая: блок 08 разросся с 536 px содержимого на ~2400 px, и кнопки уезжали поверх ячеек 10/11. В колонке «во всю ширину» — это `align-self: stretch; width: 100%`, а не `flex-basis`. Тот же приём запрещён `.ds-caveat`: `margin-top: auto` прижимал оговорку к низу ячейки и оставлял под ней пустоту в 400 px, поэтому оговорка просто идёт в общем потоке.

Одиннадцать ячеек — длинная страница, поэтому над bento лежит липкая навигация `.ds-nav` на якорях ячеек. Клик по ссылке перехватывается и вызывает `scrollIntoView`, а `history.replaceState` пишет якорь: хеш роутера принадлежит маршрутам лаборатории, и без перехвата клик ушёл бы в «неизвестный маршрут». Активный раздел подсвечивает `IntersectionObserver`, а не обработчик `scroll`.

Акцентный чип `.ds-chip--gold` несёт акцент рамкой и тонированной подложкой (`rgb(var(--accent-gold-rgb) / 0.12)`), а текст — `--gold-text`: связка `--text-on-accent` на `--accent-gold` даёт 3.1:1 и запрещена §1.1. На ≤560px сетка образцов цветов остаётся двухколоночной: двенадцать ролей в одну колонку растягивали страницу на четыре экрана.

#### 5.2d Bento рабочего стола (`#dashboard`, `css/dashboard.css`)

Четвёртый эталон bento: сводка корпуса, хроника, дерево книг, словари, разборы, метрики и карта полноты — в одной сетке. Префикс `dw-`, ячейка `.dw-cell` + шапка `.dw-cell-head` (`.dw-num` / `.dw-cell-title` / `.dw-cell-hint`, модификатор `--accent` для итогового числа). Восемь ячеек: сводка и лента — `1 / -1`, дальше пары 8+4 и дважды 5+7, поэтому в строках не остаётся пустых колонок. Пропорции заданы классами, а `tests/dashboard.test.js` сверяет, что сумма каждой пары равна 12 и что у каждого модификатора из `js/dashboard.js` есть правило в CSS.

- **Ячейка — единственный владелец своих стилей.** `redesign.css` и `theme-parchment.css` подключаются после `dashboard.css`, и их копии `dw-`/`.book-card` молча перебивали бенто: радиус `md` вместо `-8`, `transform: none` поверх живого hover у карточки книги, `background: #ffffff` в белой теме. Дубли удалены, тест `testSingleStylesheetOwner` не даёт им вернуться; из пергаментной темы заодно убран `box-shadow` у карточек книг (тень в новом UI запрещена, §0.2).
- **Шапка ячейки забирает мету из тела.** Дата среза, число событий/книг/словарей и средняя полнота переехали в `.dw-cell-hint`: у сводки исчезли дублирующий заголовок и строка «срез данных» под каждым показателем, у «Движения исследований» — подпись-абзац (она же ломала ритм из-за меры прозы `.lab-content .module p`). Дельта-строка остаётся всегда — иначе цифры пяти показателей разъезжаются, — но нейтральный срез печатается пустым: он уже в шапке.
- **Полосы и списки — без плашек.** Бары, «Последние разборы» и «Карта полноты» стали строками-hairline (§4.8, §4.12) вместо блоков с фоном; дорожки прогресса всех виджетов выровнены на 4px (канон 3–8px), поэтому карточка книги, бар и полнота читаются одним ритмом. Ширина подписи бара и счётчик заданы flex-долями, а не фиксированными `116px`/`44px`.
- **Цвет текста ссылок — только `--gold-text`.** Hover на `--accent-gold` давал 3.1:1 на светлой подложке и не добирал AA (§1.1): теперь золото живёт в рамке и подложке, а текст берёт `--gold-text`.
- **Мобильный режим (§5.3):** все ячейки получают `1 / -1`, шапка переносится, внутренние сетки становятся двухколоночными (книги 4 → 2 колонки); горизонт не скроллится — строки обрезаются ellipsis, а не переносятся. Число в мете шапки ставит хелпер `count()`: `plural()` отдаёт только слово, и подпись читалась как «книг» без числа.

#### 5.2e Bento манифеста (`#manifest`, `css/manifest.css`)

Пятый эталон bento: 24 ячейки — сводка + 4 акта прозы + 19 смысловых блоков + выход. Префикс `mn-`, ячейка `.mn-cell` + шапка `.mn-cell-head` (`.mn-num` / `.mn-cell-title` / `.mn-cell-hint`); пропорции — пары 7+5 (сводка и выход — `1 / -1`), поэтому в строках нет пустых колонок.

- **Дубль шапки удаляется в JS, а не прячется в CSS.** Внутренние заголовки блоков практики и методологии убраны из строк `page-controller.js`, ячейка несёт единственный `h2`, а лид блока (`mn-lead`) остаётся текстом без заголовка.
- **Проза акта — полный текст в две колонки.** Хелпер `fullProse()` выводит все абзацы сразу без `details.mn-more` (первый — серифный лид через `.mn-prose p:first-child`); обёртка `.mn-prose--cols` раскладывает длинные акты в 2 колонки, на ≤760px — в одну: компактность без скрытого текста и без пустот от stretch-соседей.
- **Сводка — `dl`, а не дивы.** Числа (`dd`) идут первыми визуально (`dt` с `order: 2`): скринридер читает «Акты — 4», а глаз видит число сверху.

#### 5.2f Bento книгочтения (`#scripture-reader`, `css/scripture-reader-bento.css`)

Шестой эталон bento и первый, где модуль имеет **два экрана в одной разметке**. Префикс `sr-`, ячейка `.sr-cell` + шапка `.sr-cell-head` (`.sr-num` / `.sr-cell-title` / `.sr-cell-hint`); пропорции те же — пара 7+5 в каждой строке; на экране чтения правая пятёрка собрана в рельс из трёх ячеек, полноширинных блоков на нём нет. Канон §5.2a (12 колонок, hairline, тени = 0, mobile = одна колонка), но шесть отличий:

- **Внутренняя анатомия взята у модуля «Агенты».** Панель каталога `.sr-panel` повторяет `.agent-controls-panel` (hairline, `--surface-2`, radius `-8`, одна строка, счётчик-пилюля справа); группы — `.sr-group-head` (лейбл + hairline + счётчик); строка книги `.sr-book-row` — как `.agent-list-row`: 56px, gap 10px, икон-чип 32px с Lucide-глифом по категории, палео-название и статус-пилюля с точкой. Классы свои (как `.gc-card` у генераторов): анатомия общая, префикс модуля свой. Контролы панели — общие `lab-input` / `lab-select`; свой класс несёт только раскладку.
- **Заголовок ячейки перебивает модульный h2.** Селектор задан как `.module .sr-cell .sr-cell-title`: базовое `.module h2:not(:last-child)` (0,2,1) из `layout.css` сильнее одиночного класса и раздувало капитель до серифа `--text-2xl` — ровно тот же приём, что в §5.2e.
- **Ink-ячейка держит акцент золотой рамкой.** Подложка `--bg-dark` тёмная в темах light/dark/brown и почти белая в white/beige, поэтому акцент несёт `border-color: var(--border-gold)`, а текст внутри — `--text-on-dark`. В каждом экране ячейка ровно одна.

- **Экраны переключаются скрытием, а не перерисовкой.** Разметка `page-controller.js` содержит обе секции — `#sr-library` и `#sr-reading`; модуль переключает атрибут `hidden`. Перерисовка контейнера уничтожила бы запрос поиска и позицию чтения при возврате в каталог, а `dataset.loaded` (§5.2c) всё равно запрещает повторный рендер панели.
- **Навигация — горизонтальная лента, а не перенос кнопок.** `.sr-strip` = `overflow-x: auto`. Прежняя панель ставила главы и стихи в поток: Берешит давал 50 + 31 кнопку, то есть четыре экрана прокрутки до текста. Плюс числовой переход «глава:стих» (`#scripture-jump`) и стрелки `←` `→`, которые не перехватывают набор в полях ввода.
- **Разбор слова виден всегда, режим переключает предмет.** Аккордеон с анимацией `maxHeight` заменён ячейкой с сегментами «Слово» / «Буквы» (`.sr-segment-btn`, `aria-pressed`) по образцу `.vi-segment-btn`. Две разные функции рендера в одной панели были неразличимы: теперь предмет разбора задаёт режим, а Shift-клик по буквам переключает на него сам.
- **Уровень уверенности — часть разметки, а не тона текста.** Ответ ИИ печатается слотами (ADR-006): локальные факты, `fact`, `interpretation`, `hypothesis` (пунктирная рамка + обязательная оговорка `.sr-caveat`), `warnings`, пилюля `confidence`. Цвет несёт только пилюля; текст гипотезы никогда не печатается как факт (§11).
- **Экран чтения: текст 7 + рельс 5, а не четыре разрозненные ячейки.** 01 «Текст» занимает 7 колонок и остаётся липким; 02 «Путь по тексту», 03 «Разбор слова» и 04 «Разбор свидетельств» собраны в единый `.sr-rail` (тот же приём, что в §5.2g). Мобильный закон прежний: до 900px рельс становится статичным столбиком.
- **Техническая сборка цепочек — в палео-конструкторе, без спрятанного списка.** Прежний `<details><summary>Механика</summary>` прятал цепочки слов (`слово · слово → слово`) за вторым кликом, хотя они не длиннее паспорта строки. Список удалён, а вместе с ним осиротевшие `.scripture-assembly-details` / `.scripture-assembly-words` / `.scripture-assembly-word`. Формулировки стихов и функция стиха остались на своих местах: Weaver по-прежнему получает `chains`.
- **Текст и поверхности берут разные золота.** Статус-пилюля «Есть данные» печатает `--gold-text`: заливка `--accent-gold` под текстом AA не добирает (§1.1). Чипы глав/стихов и поле перехода внутри ink-ячейки берут `--text-on-dark`, а не `--text-secondary`, — в тёмных темах светлый вторичный текст на чёрной ячейке нечитаем.

Положение чтения живёт в хеше (`history.replaceState` → `#scripture-reader?book=…&verse=…`), а не в состоянии модуля: ссылкой на стих можно поделиться, а «назад» возвращает в каталог. Плюс `alephy_scripture_last_v1` для «продолжить чтение» и полоса прогресса по §4.12. Ошибка загрузки каталога печатается внутри ячейки поиска (`#sr-books`), а не затирает весь модуль.

### 5.2q Паспорт агента (`#ai-agents` → агент → секция «ПАСПОРТ АГЕНТА», `css/agent-passport.css`, `js/agent-passport.js`)

Десятый эталон bento: внутренний паспорт агента, который работает с кодовой базой. Общий шаблон паспорта (ЗАПУСК / СВЯЗИ / РЕЗУЛЬТАТ) остаётся общим для всех агентов; секция «ПАСПОРТ» добавляется только агентам с флагом `passport` в `getAgentMapData()` — поэтому она и называется паспортом, а не заменяет базовый экран. Префикс `ap-` (agent passport), сетка `.ap-bento` на 12 колонок, ячейка `.ap-cell` (hairline `--line`, radius `-8`, тени = 0), шапка `.ap-cell-head` по §4.1a — `.module` в селекторе, `border-bottom: 0`, лейбл `--ui-11`/700/`var(--tracking-caps)`.

| Ячейка | Пропорции | Содержание |
|---|---|---|
| 01 «Контракт агента» | 5 колонок | Вход, выход, эндпоинт запуска и **границы** — что агент сознательно не делает (§6) |
| 02 «Канон проверки» | 7 колонок | Ссылка на параграф DESIGN-SYSTEM + правила «свойство · значение · зачем» в две колонки |
| 03 «Аудит канона» | 8 колонок | Сводка (числа) + построчные расхождения: файл, селектор, нарушенное правило, что исправить |
| 04 «Код агента» | 12 колонок | Путь, размер, исходник модуля с сервера, копирование |
| 05 «Задачи лаборатории» | 4 колонок | Готовые запросы; «Подставить» кладёт текст в поле ЗАПУСК |

- **Тулбар — оболочка `.lab-toolbar` по §4.7**, не своя панель: поиск по строкам паспорта, счётчик `.lab-toolbar-count` и «К списку агентов» справа. Нижняя плашка `.agent-detail-back` у агентов с паспортом не рисуется — возврат живёт в тулбаре, чтобы хром страницы был одной строкой.
- **Пустот между ячейками нет** — `align-items: stretch`, а не `start`. Короткая ячейка в ряду иначе оставляет под собой пустую полосу, и сетка читается лестницей. Высоту добирают содержимым, а не растягиванием строк: пустое состояние (`flex: 1`, центрируется), список задач (`space-between`), а контракт и канон внутри ячейки разложены в две колонки — в одну колонку 01 и 02 расходились по высоте вдвое.
- **Поиск фильтрует строки `.ap-finding` / `[data-ap-searchable]`** на месте и обновляет счётчик; при пустом результате под сеткой появляется честное empty-state (§4.6), а не «0 найдено».
- **Источник кода — сервер**, `GET /api/agents/source?agent=<имя>`, читает файл с диска, поэтому правка Python подхватывается без синхронизации статики. Имя приходит из белого списка `AGENT_SOURCES` в `server.py`: произвольный путь не читается. Ошибка и офлайн дают `null` — ячейка «Код агента» показывает команду запуска сервера, паспорт остаётся рабочим.
- **Агент — не декорация.** У каждого агента с паспортом своя предметная область (у фронтенд-разработчика — аудит §4.1a по `researchlab/css`). Аудит исполняется на настоящем репозитории и печатает реальные числа; выдуманные значения запрещены (§6).
- **Мобильный закон §5.3:** ≤900px все ячейки → `1 / -1`, ≤640px расхождения складываются в одну колонку, код ограничен 240px по высоте.

- **Шаг кликабелен весь, а не только имя.** Карточка `pd-step` — ссылка `pd-step-link` (`#ai-agents/<id>`), стрелка `move-up-right` показывает переход; ссылка перезаписывает имя в разметке, а не висит в конце строки.

- **Описание — на странице, а не только в hero.** `pipeline.description` печатается в ячейке 01 целиком; hero-подзаголовок остаётся краткой подводкой, а факты (тип, runner, число этапов, запусков) живут в `pd-facts` — паспорт читается без скролла к шапке.
- **Прогон выбирается из истории.** `pipelineDetailState { pipelineId, runId }` помнит открытый прогон: кнопка «Открыть результат» в истории перерисовывает только страницу (данные перезапрашиваются, но выбор — один источник правды), смена пайплайна сбрасывает `runId`. По умолчанию показан последний готовый (`findPipelineResult`).
- **Ошибки в истории видны.** Список раньше фильтровал `status === 'ready'` и терял неудачные прогоны; теперь строки несут реальный статус, а «Открыть результат» предлагается только у готовых.
- **Офлайн гасит запуск с причиной.** `checkAgentServer()` пишет hint в шапку ячейки 02 (`data-state="ok|off"`) и блокирует запуск/запись с `PIPELINE_OFFLINE_HINT` в тултипе — как в списке пайплайнов (§4.4), но теперь и на детальной странице.
- **Срез этапа без JSON-дампа.** `agentTrace[i]` показывается как `dl.pd-step-facts` (статус, итерация, до 5 наблюдений); raw JSON остаётся в экспорте JSON — дампом в интерфейс его показывать нельзя.
- **Статусы диаграммы — по следу выбранного прогона.** Узлы `.pipeline-diagram-node` получают `data-status="done|pending"` после рендера; диаграмма та же, что в карточке списка, — два экрана читают один визуальный язык.
- **Мобильный закон §5.3:** ≤900px ячейки 01–04 → `1 / -1`; ≤760px действия столбцом с тап-таргетом 40px, факты одной колонкой, история — кнопки во всю ширину строки.

### 5.3 Мобильный закон
390px: одна колонка; каждый блок = ширина контейнера шапки; overflow-x = 0; тап-таргеты ≥40px; композеры в одну строку (flex-1, min-width 0).

## 6. Статусы и уверенность (эмет/шекер в UI)

| Метка | Визуал | Значение |
|---|---|---|
| факт / проверено / эмет | точка-бейдж золота | подтверждено источником |
| интерпретация / в работе | нейтральный (hairline, muted) | рабочая версия |
| гипотеза / спорно | приглушённый (opacity .6) | требует проверки |
| разрушение / ошибка | `--accent-red` | дозированно |

Легенда едина для всех модулей (обучение, исследования, реконструкция НЗ). Новая метка = правка этой таблицы.

Каталог «Исследования» (#researches) кодирует эти же метки точками `.res-dot-*` (css/research-library.css), цвета наследуются от палитры бейджей `.exposure-badge-*` (ExposureCase.CONFIDENCE_META): проверено `#2f6b1f`/dark `#7bc47b` · требует проверки `#93620a`/dark `--accent-gold` · гипотеза `#2455a4`/dark `#8fb4ea` · спорно `#a3392c`/dark `#e08a8a`. Точка всегда несёт `title`/`aria-label`.

Палео-таймлайн (`#timeline`) кодирует **тип события** точками `.tl-status-dot--*` (css/linear-timeline.css): событие `--status-green` · текст/перевод `--accent-gold` · находка/рукопись `--status-violet` · подмена `--status-red` · концепт `--status-blue` · буквенный слой `--status-teal` · персона `--status-amber`. Уверенность даты — бейдж `.tl-confidence--*` (факт/интерпретация/гипотеза) в палитре этой таблицы: факт → зелёный, интерпретация → янтарный, гипотеза → красный. Чипы-эры каталога строятся из поля `era` в `data/timeline.json` (словарь `ERAS` в `js/timeline.js`); хардкод ID эр в коде запрещён (ADR-002). Режим сравнения (`#timeline/compare/<idA>/<idB>`, только датированные ленты) кодирует стороны тегами A/B: A — золото (базовая лента), B — `--status-blue`; строка сводной хронологии кликабельна и ведёт к событию исходной ленты. Кросс-ссылки события — пилюли `.tl-event-link` с внутренними hash-адресами.
