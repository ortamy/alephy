# Анти-slop чек-лист: Research Lab и лендинг

- **Файл:** `docs/10-DESIGN/ANTI-SLOP-CHECKLIST.md`
- **Статус:** Активный
- **Опора:** `docs/10-DESIGN/DESIGN-SYSTEM.md`
- **Связанные:** `docs/09-GUIDES/A11Y-MINIMUM.md`, `docs/09-GUIDES/PERFORMANCE.md`

## Зачем

Слоп — узнаваемый вид «сгенерированного интерфейса»: чужие цвета и тени, симметричные
сетки без иерархии, анимация ради анимации, текст без источника, эмодзи вместо иконок.
Этот файл не заменяет `DESIGN-SYSTEM.md`, а вытаскивает из него **проверяемое**:
что смотреть в диффе, чем подтвердить и какой элемент репозитория считается эталоном.

## Как пользоваться

Порядок: машинные грепы (A) → глазами по признакам (B) → смысл и тексты (C) → вердикт.
Вердикт по каждому изменению — один из трёх:

| Вердикт | Когда |
|---|---|
| **принято** | нарушений нет, новый токен/паттерн не вводился |
| **принято с записью** | добавлен токен, компонент, исключение из закона — сначала правка `DESIGN-SYSTEM.md`, потом код (§8.1) |
| **отклонено** | нарушение закона из §0.2 без записи в дизайн-системе |

Скрин для вёрстки — after-доказательство в `tasks/<task>/` (§8.4). Скрин не заменяет
грепы: консистентность токенов проверяется кодом, а не изображением.

## C. Смысл и тексты

- UI различает **факт / интерпретацию / гипотезу**; уверенность видна в интерфейсе,
  а не только в тексте (§6). Новые метки — правкой таблицы §6.
- Палео-лексика живёт в контенте и **никогда в хроме** — кнопках, инпутах, сайдбаре,
  тулбарах (§0.2).
- Заполнители-обещания («революционный», «уникальный», «Lorem») — слоп: вместо них
  проверяемая формулировка с источником или статусом.
- Глагол-когнат не подлежащее (правило Weaver, `.clinerules` §11).
- Иврит — `lang="he" dir="rtl"`, библейский иврит — `lang="hbo"`
  (`docs/09-GUIDES/A11Y-MINIMUM.md`).

## D. Если нужно новое

1. Новый токен, компонент, исключение из закона — **сначала строка в `DESIGN-SYSTEM.md`,
   потом код** (§8.1). Незаписанное исключение = отклонённое изменение.
2. Зависимость > 20 KB gzipped или новый подход — ADR в `docs/decisions.md` (§8.2).
3. Скрин-доказательство вёрстки — в `tasks/<task>/`, а не в корне продукта (§8.4).
4. Тронул файл — оставь чище: один мелкий рефакторинг в рамках задачи (§8.5).

## E. Definition of done для UI-правки

- [ ] A1–A9 чисты по изменённым файлам (или расхождение записано в `DESIGN-SYSTEM.md`).
- [ ] B1–B13 чисты по изменённым файлам.
- [ ] Новая ячейка bento: заголовок `--ui-11`/700/`var(--tracking-caps)`/`.module` в селекторе, чёрка только на шапке во всю ширину (§4.1a).
- [ ] Обе темы проверены (плюс white/beige, если правка касалась палитры).
- [ ] `prefers-reduced-motion`: новые анимации отключаются.
- [ ] 390px: одна колонка, `overflow-x: 0`, тап-таргеты ≥ 40px (§5.3).
- [ ] Клавиатура: фокус видим, `/` — поиск, Escape — оверлеи (§7).
- [ ] Контраст: текст ≥ 4.5:1, иконки и рамки-состояния ≥ 3:1 (§7).
- [ ] After-скрин в `tasks/<task>/`.
- [ ] Новый токен/паттерн — есть запись в `DESIGN-SYSTEM.md` (§8.1).

## Ограничения

Чек-лист — операционный слой поверх канона и не заменяет аудит доступности,
производительности и smoke-прогон. Числа (контраст, тап-таргеты, бюджеты) живут в
`DESIGN-SYSTEM.md` (§7), `docs/09-GUIDES/A11Y-MINIMUM.md` и
`docs/09-GUIDES/PERFORMANCE.md`; при расхождении приоритет у канона.
