# Безопасность: чек-лист перед коммитом

- **Файл:** `docs/09-GUIDES/SECURITY-CHECKLIST.md`
- **Статус:** Активный
- **Опора:** `docs/01-ARCHITECTURE/ARCHITECTURE.md`
- **Связанные:** `docs/09-GUIDES/ERROR-HANDLING.md`, `docs/09-GUIDES/PERFORMANCE.md`, `docs/decisions.md`

## Модель угроз

Что реально существует в проекте:

- **статический сайт** (GitHub Pages): серверного кода нет, утечка = секрет в репозитории;
- **локальный Flask API агентов** `products/agents/server.py` — слушает `127.0.0.1:5000`,
  `debug=False`, CORS включён по умолчанию и снимается флагом `--no-cors`;
- **браузерное хранилище** (`localStorage`) для прогресса, черновиков и офлайн-снимков;
- **внешний бэкенд-адаптер** пока отсутствует: Supabase не подключён.

Главный практический риск — XSS через данные (JSON, тексты исследований, ответы агентов),
второй — секреты в истории git.

## 1. Экранирование

- Канон один: `AlephyUtils.escapeHtml` (`js/utils.js`) — экранирует `& < > " '`.
  Кавычки обязательны: значения попадают в атрибуты (`aria-label`, `data-*`).
- Локальная обёртка модуля обязана делегировать канону (в модулях это помечено
  комментарием «Канон в js/utils.js»). Вторая реализация экранирования — дефект.
- `innerHTML` допустим только для собственных шаблонов; любое значение из данных,
  файла или API вставляется через `escapeHtml`. Для простого текста — `textContent`.
- Проверка глазами по каждому вхождению:
  ```bash
  git grep -n "innerHTML" -- products/website/apps/researchlab/js
  ```

## 2. Сеть и API

- Страница обращается только к своему origin и к локальному API `http://127.0.0.1:5000`.
- `server.py` — инструмент разработчика, не прод-бэкенд: не публиковать в сеть,
  не открывать на `0.0.0.0` без явной задачи и не держать `debug=True`.
- Внешние ссылки — с `rel="noopener"` (и `noreferrer` для сторонних доменов).

## 3. Service Worker

- `sw.js` перехватывает только GET того же origin; чужие домены не кэшируются.
- При изменении кэшируемых файлов поднимать `CACHE_NAME` — иначе у пользователя
  остаётся старая версия, и дефект воспроизводится только у него.
- Помнить про следствие для тестов: `page.route()` не видит запросы, обслуженные SW
  (см. `docs/08-AUDITS/KNOWN-SMOKE-FAILURES.md`).

## 4. Секреты

- `.env`, `secrets.json`, `*.key` — в `.gitignore`; ключи не попадают в исходники,
  документацию, скриншоты, логи и тексты ошибок.
- Анон-ключ внешнего бэкенда безопасен только вместе с RLS на всех таблицах
  (правило на будущее: адаптер Supabase в репозитории отсутствует).
- Секретов нет в `data/*.json` — данные лаборатории публичны по определению.

## 5. Чек-лист перед коммитом

```bash
git status --short
git diff --check
git grep -nE "(api[_-]?key|secret|token|password|BEGIN [A-Z ]*PRIVATE KEY)" -- . ':(exclude)*.md'
```

Падение любой строки — стоп: сначала устранить, потом коммит.

## При инциденте

1. Отозвать/сменить скомпрометированный ключ — до любых правок репозитория.
2. Убрать секрет из рабочего дерева.
3. Оценить историю: `git log -p -- <файл>`. Если секрет попал в коммиты, перепись
   истории — отдельная согласованная задача, а не побочный эффект фикса.
4. Если меняется сама практика (отказ от подхода, новый внешний сервис) — запись ADR
   в `docs/decisions.md`.

## Запрещено

- `eval`, `new Function`, `innerHTML` с внешними данными.
- Секреты и токены в исходниках, доках и тестовых данных.
- Публикация локального агентного сервера в открытую сеть.
- «Временное» отключение экранирования ради быстрого рендера.
