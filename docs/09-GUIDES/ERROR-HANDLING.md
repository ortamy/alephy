# Ошибки и деградация интерфейса

- **Файл:** `docs/09-GUIDES/ERROR-HANDLING.md`
- **Статус:** Активный
- **Опора:** `docs/01-ARCHITECTURE/ARCHITECTURE.md`
- **Связанные:** `docs/09-GUIDES/A11Y-MINIMUM.md`, `docs/09-GUIDES/PERFORMANCE.md`, `docs/08-AUDITS/KNOWN-SMOKE-FAILURES.md`

## Принцип

Ошибка — это состояние интерфейса с действием, а не пауза. Пользователь должен
видеть: что случилось, что делать, куда нажать. Вечный спиннер считается ошибкой.

## Четыре уровня деградации

1. **Модуль не загрузился.** Гард в `apps/researchlab/js/page-controller.js`:
   `WATCHDOG_MS = 8000`; если через 8 с в панели всё ещё виден спиннер — рендерится
   error-state `[data-module-error]` (`.lab-alert-error`, `role="alert"`) с кнопкой
   «Повторить». Падение `init()` переводит панель туда же сразу, без ожидания таймаута.
2. **Данные без сети.** `fetch` обязан иметь локальный fallback: снимок в `localStorage`
   (`js/paleo-keyboard.js`) или degraded-state с кнопкой «Повторить»
   (`js/lab-search.js`: пишет `console.warn('[LabSearch] fallback: …')` и отдаёт пустой
   набор вместо исключения).
3. **Офлайн.** `sw.js`: навигация — network-first с откатом на кэш `index.html`;
   статика — stale-while-revalidate; если ресурса нет ни в кэше, ни в сети — ответ
   `503 «Ресурс временно недоступен.»`
4. **API агентов недоступен.** `products/agents/server.py` — локальный процесс, которого
   может не быть: вызов деградирует (`OllamaError` в `ollama_adapter`), интерфейс
   показывает статус, а не пустую панель.

## Правила

- Каждый `fetch` — с проверкой `response.ok` и обработкой отказа сети.
- Текст ошибки: что случилось + что делать. Без стеков, путей, английских кодов.
- Технические подробности — в консоль, с префиксом модуля (`[PageController]`, `[LabSearch]`).
  `console.log` в рабочем пути не оставлять.
- Пустой `catch {}` — только для необязательных побочных действий и с объясняющим
  комментарием (канон: `cache.put(request, response.clone()).catch(() => {})` в `sw.js`).
- Статусы и ошибки объявляются скринридеру (`role="status"` / `role="alert"`) — см.
  `docs/09-GUIDES/A11Y-MINIMUM.md`.
- Бюджет ожидания спиннера в тесте (`SPINNER_BUDGET_MS`, 7 с) держится ниже гарда (8 с):
  до порога модуль «ещё грузится», после — ошибка. Подробности и история флака —
  `docs/08-AUDITS/KNOWN-SMOKE-FAILURES.md`.

## Как воспроизводить

1. DevTools → Network → Offline, затем перезаход и обновление на маршруте.
2. Остановить `products/agents/server.py`: зависящие от API модули показывают статус,
   а не пустоту.
3. Оборвать данные: `page.route('**/*.json', route => route.abort())` — проверка fallback.
4. `cd products/website/apps/researchlab && npm run test:smoke` — маршрутный прогон
   проверяет отсутствие `[data-module-error]`, uncaught-ошибок и вечных спиннеров.

**Важно для тестов:** `page.route()` не перехватывает запросы, обслуженные Service Worker.
Для таких проверок Service Worker блокируется: `browser.newContext({ serviceWorkers: 'block' })`.

## Запрещено

- `alert()` и `confirm()` для сообщений об ошибке.
- Показ пользователю сырого текста исключения или HTTP-кода без пояснения.
- Бесконечный спиннер как «нормальное» состояние загрузки.
- `catch` без обработки и без объясняющего комментария.
