# Пайплайны агентной системы

Документ описывает **фактический** реестр: что запускается, из каких шагов и в каком порядке. Числа здесь намеренно не приводятся — счётчики живут в автоблоках `ARCHITECTURE.md` и берутся из диска, а ручная цифра стареет молча (ADR-016).

Пайплайны делятся по способу запуска: это разные классы, и смешивать их нельзя.

- **Пайплайны-карточки** — записи `data/pipelines.json`; запускаются через `POST /api/pipelines/<id>/run` или голосом оркестратора.
- **Пайплайн-эндпоинт** — `scripture_analysis.py`; вызывается своим маршрутом сервера мимо оркестратора.
- **Движок** — `pipelines/core.py`; не пайплайн, а три способа собрать цепочку.

## Движок: чем выражается цепочка

- `run_steps` — линейная цепочка. Пустой результат шага (`None` или `{}`) останавливает пайплайн: система не молотит впустую.
- `run_loop` — цикл: виток `cycle_steps`, затем агент сходимости (`agents/convergence.py`) снимает подпись витка и решает, сошёлся ли поток (эмет), принёс ли новые улики (поток) или встал (Мавет). Защита от вечного круга — `max_iterations`; `shmita_every` прощает накопленный шум; результат несёт `iterations`, `converged`, `stalled`.
- `run_fanout` — веер (ADR-019): несколько независимых веток от одного пакета, затем общее сведение. Ветка идёт по своей копии пакета с полем `branch_id`, пустая ветка не глушит веер, а сводка `branches` показывает, кто что принёс.

Пайплайн, созданный в интерфейсе без Python-раннера, исполняется по карте русских имён агентов (`server.AGENT_FUNCTIONS`), а движок выбирается по типу карточки: `linear` — цепочка, `loop`/`spiral` — витки со сходимостью (ADR-020).

## Пайплайны-карточки

### Исследовательские

| Пайплайн | Шаги | Что делает |
|---|---|---|
| `word_analyzer` | исследователь → семитолог → разоблачитель → редактор → сборщик | Разбор слова: корень, палео-механика, диагностика подмен перевода. |
| `verse_comparator` | компаратор → критик → редактор → сборщик | Кладёт рядом текстовых свидетелей и карту расхождений. |
| `research_builder` | архитектор потока → связной → технический писатель → сборщик | Собирает разрозненные наблюдения в единый отчёт. |
| `paleo_translation` | исследователь → переводчик палео → семитолог → проверяющий → редактор → сборщик | Обратный перевод: от современного термина назад к палео-образу. |
| `research_audit` | ревьюер кода → критик → проверяющий → редактор → сборщик | Карта «эмет / шекер» для готового исследования. |
| `mechanism_scanner` | исследователь → разоблачитель → критик → сборщик | Тип искажения и механизм подмены. |
| `verse_reconstruction` | компаратор → переводчик палео → разоблачитель → проверяющий → сборщик | Восстановление палео-смысла стиха независимо от переводов. |
| `witness_council` | веер: свидетели, палео-образ, подмены → проверяющий → критик → сборщик | Три независимых прохода по одному вопросу и общее сведение; сводка веток — в результате полем `branches`. |

### Циклические

| Пайплайн | Шаги витка | Что делает |
|---|---|---|
| `critique_loop` | редактор → критик → проверяющий | Гоняет черновик до валидного витка без новых замечаний. |
| `gap_cycle` | исследователь → разоблачитель → проверяющий | Копит пропуски корпуса в честную карту до сатурации. |
| `spiral_swiva` | связной → исследователь → переводчик палео → проверяющий | Спираль: связной расширяет горизонт до сатурации. |
| `dialectic_loop` | компаратор → критик → проверяющий | Тезис компаратора против критика, пока не выйдет эмет или чёткий шеол. |
| `midrash_recursion` | исследователь → переводчик палео → проверяющий | Перевод входит в собственный вывод и перечитывает образ как термин. |
| `shmita_loop` | редактор → критик → проверяющий (шмита каждые 2 витка) | Прощает накопленный шум; в результате — `shmita_resets`. |

### Системные (проект, а не корпус)

| Пайплайн | Шаги | Что делает |
|---|---|---|
| `ui_canon` | фронтенд-разработчик → сборщик | Читает CSS лаборатории и считает расхождения канона ячейки bento (§4.1a): специфичность, сброс черты, кегль, вес, трекинг. Итог аудита — заголовок результата. |
| `registry_audit` | архитектурный сканер → проверяющий → сборщик | Показывает расхождения реестров: карточка без раннера, раннер без карточки, модуль пайплайна без карточки. Только чтение. |
| `arch_keeper` | сканер → критик → планировщик → писатель → сход | Сверяет паспорт архитектуры с диском и перерисовывает фактические блоки. Единственный пайплайн с правом записи (`"writable": true`). |

### Пайплайн-эндпоинт

- `scripture_analysis.py` — разбор палео-фрагмента по слотам «факт / трактовка / гипотеза» (ADR-006). Вызывается своим маршрутом сервера и не входит в `orchestrator.ROUTES`.

## Чего в реестре нет и почему

Правило: карточка не добавляется под агента, которого нет. Пустая карточка обещает работу, которой система не делает (ADR-021). Ниже — сценарии, которым нужен новый агент, а не новая перестановка существующих:

- **`cleaner` / `docs_manager`** — очистка временных файлов и синхронизация документации. Нет агента с правом удаления: право записи — отдельное решение (сейчас запись разрешена только `arch_keeper` и только после гейта).
- **`tester` / `validator`** — прогон тестов и валидация данных. Нет агента, который запускает тесты: smoke и unit живут в CI (`.github/workflows/`), а не в пайплайне.
- **`designer` / генерация интерфейсов** — `frontend.py` намеренно только аудирует канон и не верстает.
- **`connector`** — перекрёстные связи между исследованиями: нет агента, который читает корпус исследований целиком.
- **`idea_generator`** — идеи по пробелам корпуса: нет агента, который знает, чего в корпусе не хватает.
- **`run_quorum` и `run_dag`** — примитивы композиции, отложенные с явной причиной: кворум из одинаковых детерминированных голосов был бы театром, граф без второго потребителя — преждевременным обобщением (ADR-019).
