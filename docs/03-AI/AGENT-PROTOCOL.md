# Протокол обмена агентной системы «Алефи»

**Метаданные файла**
- **Файл:** `docs/03-AI/AGENT-PROTOCOL.md`
- **Версия:** 1.0
- **Статус:** Активный
- **Назначение:** Единый контракт обмена агентов: пакет, след (trace/agentTrace) и формы кооперации.

Машинная версия контракта — `products/website/apps/researchlab/data/agents/protocol.json`. Источники правил — `products/agents/pipelines/core.py`, `products/agents/agents/common.py`, `products/agents/agents/convergence.py`.

---

## 1. Что описывает протокол

«Протокол» здесь — инженерный смысл: путь (Дэрех), способ, которым агент передаёт работу другому и как движок читает след. Это не методологический `docs/06-METHODOLOGY/PROTOCOL.md` (общий протокол разоблачения) и не правила постановки задач (`AI-WORKFLOW.md`).

Протокол описывает то, что уже работает, и не вводит новых сущностей. Единственный носитель состояния — пакет. У агента нет глобального состояния: он читает пакет и возвращает пакет.

## 2. Контракт агента

Каждый исполняемый агент — функция `(data) -> data`: принимает пакет, возвращает обновлённый пакет (или пустой результат — см. §5). Контракт задан в `agents/common.py` (`agent_contract`) и повторяется паспортом каждого агента в поле `contract`.

- Вход: `dict` с обязательным полем `query`.
- Выход: `dict`, сохраняющий `trace` и `agentTrace`.
- Вызов: `POST /api/run` (сервер `products/agents/server.py`).

## 3. Пакет

Пакет создаётся `common.packet(query, **values)` и несёт два «конверта» следа и исследовательские поля:

```json
{
  "query": "разбери слово Берешит",
  "trace": [],
  "agentTrace": [],
  "iteration": 0
}
```

- `query` — единственное обязательное поле.
- `trace` и `agentTrace` — конверты следа (§4); их пишут агенты, а не движок.
- Остальные поля (`term`, `root`, `paleo_image`, `exposures`, `critique`, …) — исследовательские улики: движок их не толкует, а передаёт по цепочке.
- `iteration` осмысленно только в цикле: `run_loop` присваивает `0` в начале. В линейной цепочке и веере поля нет, и `record` пишет `iteration = 0`.

## 4. След: trace и agentTrace

Каждый вызов агента пишется в пакет через `common.record(data, agent, **values)` — два представления одного факта:

- `trace` — плоский список id агентов в порядке вызова: короткий ответ на вопрос «кто и в каком порядке».
- `agentTrace` — журнал с подробностями. Запись:

```json
{
  "agentId": "researcher",
  "iteration": 0,
  "status": "done",
  "input": { "query": "…" },
  "observations": [{ "field": "term", "value": "…" }],
  "decisions": [],
  "hypotheses": [],
  "limitations": [],
  "output": { "term": "…" }
}
```

- `iteration`: `0` — линейная цепочка, `1..N` — номер витка цикла. По нему видно, какой виток дал какую улику.
- `input`: снимок пакета до вызова, без конвертов (`trace`/`agentTrace`/`result`) — журнал не раздувается следами.
- `observations`: по паре `{field, value}` на каждое поле, записанное шагом.
- `decisions`, `hypotheses`, `limitations`: зарезервированы под явное разделение «факт / интерпретация / гипотеза». `record` заполняет их пустыми; агент может наполнить вручную.
- `output`: снимок полей, которые шаг записал.

`record` не удаляет улики и не переписывает след: один вызов — одна запись в `trace` и одна в `agentTrace`.

## 5. Правило остановки

Пустой результат шага — `None` или `{}` — останавливает пайплайн (`core.is_empty`). Система не молотит впустую: агент, которому нечего добавить, честно обрывает цепочку, а не пропускает шаг молча.

В веере пустая ветка не глушит соседние: ветка помечается `empty: true` в сводке `branches`, а решение о сведении принимают шаги `join` (§6.3).

## 6. Формы кооперации

Движок `pipelines/core.py` даёт три способа собрать агентов. Больше форм в реестре нет — `run_quorum` и `run_dag` отложены осознанно (ADR-019).

### 6.1. linear — `run_steps`

Агенты вызываются по очереди по одному пакету. Первый пустой результат останавливает цепочку.

### 6.2. loop / spiral — `run_loop`

Виток `cycle_steps`, затем агент сходимости `convergence` (§7). Поля-результаты цикла: `iteration`, `converged`, `stalled`, `convergence_history`, `shmita_resets`.

- `max_iterations` — защита от вечного круга. Витки исчерпаны, сходимости нет → пакет помечается `stalled: true` (Мавет), разбор — за человеком.
- `shmita_every` + `reset_fields` — «шмита-сброс»: каждые N витков прощаются растущие поля (`gaps`, `exposures`, `horizon`). Ядра цикла из `core._PROTECTED` не трогаются, поэтому подпись витка может стабилизироваться и цикл сойдётся.

### 6.3. fanout — `run_fanout`

Несколько независимых веток от одного пакета, затем общее сведение `join`.

- Каждая ветка идёт по своей копии пакета с полем `branch_id`; улики ветки не видны соседям — иначе «независимость» была бы только словом.
- Сводка `branches` в результате: `{id, steps, empty, fields}` — кто что принёс.
- Ветки выполняются по очереди: шаги — детерминированные функции одного процесса, параллельность не дала бы ничего, кроме путаницы в следе.

## 7. Сходимость цикла

Агент `convergence` (`agents/convergence.py`) снимает подпись витка по ключевым исследовательским полям и решает, сошёлся ли поток.

- Подпись (`_signature`) строится по фиксированному списку полей; палео-образ сравнивается без `depth` (иначе рекурсия не сошлась бы), `context_wave` в подпись не входит (он меняется каждый виток даже при стабильном контексте).
- Правило: `converged = valid and not changed`. Первый виток сойтись не может — нужна минимум одна сверка.
- Статусы: **эмет** (новых улик нет, поток сошёлся), **поток** (свежие данные, продолжаем), **Мавет** (повтор без валидности — ручной разбор), **Тоху** (неопределённость, продолжаем наблюдение).
- Поля `convergence`: `iteration`, `converged`, `stalled`, `delta`, `fresh_evidence_count`, `status`, `notes`, `_signature`.

## 8. Границы: чтение и запись

- По умолчанию агент только читает репозиторий и пишет в пакет. Запись на диск — отдельное право, а не свойство шага.
- Право записи есть только у пайплайнов из белого списка `server.WRITABLE_PIPELINES` (сейчас — `arch_keeper`) и только по явному флагу. Список проверяется на сервере, а не в интерфейсе.
- Протокол обмена записи не подразумевает: он описывает передачу пакета, а не изменение файлов.

## 9. Чего в протоколе нет

- `run_quorum`, `run_dag` — примитивы композиции, отложены с явной причиной (ADR-019): кворум одинаковых детерминированных голосов был бы театром, граф без второго потребителя — преждевременным обобщением.
- Версионирования схемы в рантайме: `schemaVersion` есть у паспортов и у этой спецификации, но агенты не проверяют её на каждом вызове.
